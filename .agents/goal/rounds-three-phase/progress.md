发现：真实浏览器里 `document.hidden` 会被反复短暂翻转；原实现对每次 `visibilitychange` 立即暂停，导致视觉审查过程中一局被冻结，按钮点按也因「元素被禁用」失败。

- 新增纯逻辑 `src/core/lifecycle.ts`：`decideBackgroundPause` 只在持续后台 ≥0.5 秒且仍处于游玩时暂停；失焦与瞬时抖动忽略。规格要求的「真实切后台必须暂停」保持不变。
- 新增 `tests/lifecycle.test.ts` 5 条行为测试（先失败再通过）。
- 暂停文案区分原因：`resumeNote` 显示「你切到了后台，值班已自动暂停」；重新开始一局时清空。
- HUD 每帧写 `transform` 导致自动化判定元素不稳定：体力条、效果条、卡槽进度改为分档比较后再写 DOM。

### 2026-10-31 · 轮次 5：后台暂停与同类边界的最终形态

初版「逐帧累加后台时长」在无头/自动化环境会被完全节流的动画帧架空；`page.waitForTimeout` 期间侧标签一开一合也可能让浏览器合成「隐藏→恢复」两次事件而丢失隐藏时刻。

最终实现（`src/core/lifecycle.ts`，6 条行为测试）：
- `decideBackgroundPause`：基础规则——必须仍在游玩、持续离开 ≥0.5 秒、且不是「仅失焦」。
- `pauseAfterBackground`：回前台时按真实时间差判定；若隐藏与恢复落在同一时刻（无头浏览器常见），只要期间在游玩就要求确认后继续。
- `advanceBackgroundClock`：只保留为诊断辅助，不单独触发暂停。

真实浏览器复测：新开标签页并停留后回前台，`phase` 切到 `paused`，HUD 文案显示「你切到了后台，值班已自动暂停」，点「继续值班」恢复正常；随后胜利与 `R` 重开照常。

已记录但未在本轮修复：自动化里多次快速切换标签页后，浏览器可能忽略后续合成的 `visibilitychange`（`document.hidden=true` 却未进暂停）；这属于无头 Chromium 的合成行为，真人单次切换不会被吞，后续长期回归时继续验证。

验证：`npm run test` 4 文件 / 52 测试通过；`npm run typecheck` Exit Code 0；`npm run build` Exit Code 0。

### 2026-10-31 · 轮次 7：包体拆分与性能测量

- **主包拆分**：`vite.config.ts` 用函数式 `manualChunks` 把 three.js 单独成块。实测业务入口从 616 kB 降到 **55 kB**（gzip 20 kB），three 独立 561 kB（gzip 140 kB）可被浏览器长缓存；场景改动不再让玩家重下 three。构建警告随之消失。
  - 注意：rolldown 只接受**函数**形式的 `manualChunks`，对象形式会直接构建失败。
- **性能实测（1280×720，无头 Chromium）**：开始页 / 游玩 / 开灯三种状态的中位帧间隔都约 33.4 ms（≈30 fps），开灯未带来额外下降；绘制调用 340–511。这个数值受无头环境 30 Hz 合成限制影响，**不能当作真实笔记本 60 fps 的证明**，已按实测记录。
- **搜索圈只在搜索/广播时出现**：追逐中不显示，避免误解为「已丢失玩家」。
- **焦点兜底**：浏览器漏发 `visibilitychange` 时，回到前台的第一帧补做暂停判定。

回归发现并厘清的两点（非缺陷）：
1. 调试时把值班员放到玩家 2 m 内，追逐会在 0.9 秒内结束（被抓），因此「红框还没消失就结算」是正确行为。danger 窗口的时间线实测：进入追逐后约 0.1→0.88 秒可见，随后被 `lost` 收走。
2. 因此「追逐红框完整显示 1.2 秒」只能用 `dangerWindow` 的 3 条单元测试证明，浏览器端只能证明「进入追逐时出现、离开时消失」。

验证：`npm run typecheck` Exit Code 0；`npm run test` 5 文件 / 55 测试（轮次 8 后为 6 文件 / 62 测试）通过；`npm run build` Exit Code 0，入口 55.25 kB + three 561.15 kB（轮次 8 后入口 57.88 kB）。
