# 《查房》(Rounds) 游戏策划与设计案 (GDD)

> 项目状态：已立项定稿 (Approved) · 参赛工程：VibeHacks #06

---

## 1. 核心玩法与体验目标 (Core Gameplay Loop)

- **一句话概述**：在主电源中断的公立医院躲避巡查值班员，坚持 **60 秒**直至安全门通电，利用三条伴随代价的值班指令改写医院路线逃出生天。
- **美学与氛围定位**：
  - **写实取向、明亮可读、气氛克制**：浅米、冷灰白、淡绿的公立医院配色；备用冷白灯光，地面干净，视野开阔；
  - **摒弃低俗惊吓**：无血腥、无跳吓（Jump Scare）、无持续黑暗；压迫感完全来自沉重的脚步声、转角视线博弈与倒计时。
- **路演 20 秒核心记忆点**：
  - 玩家按下 `[2]` 封门指令，防火门轰然落下挡住值班员，值班员被迫掉头绕行，而玩家自己也必须绕另一条长廊冲向刚亮起绿灯的安全门。

## 2. 核心操作与交互机制

| 按键 / 操作 | 功能定义 | 机制细节与反馈 |
| :--- | :--- | :--- |
| `W A S D` | 基础平移移动 | 正常步速约 3 m/s，无噪音。 |
| 按住 `Shift` | 奔跑加速 | 速度提升至约 5.5 m/s，消耗体力槽；在 7 米范围内会发出脚步声吸引值班员。 |
| 鼠标右键拖动 | 自由旋转镜头 | 第三人称越肩/俯视伴随视角，转角自动避开墙体遮挡。 |
| `1` | 指令：全院开灯 | 点亮走廊高光，HUD 标出值班员位置；代价：值班员视距扩大 50%。 |
| `2` | 指令：封锁走廊 | 降下指定走廊的防火门阻断通道；代价：玩家自身也无法通行该门。 |
| `3` | 指令：广播查房 | 点亮远处病房广播诱敌；代价：广播结束后值班员进入高度警觉搜索状态。 |
| `Esc` | 暂停菜单 | 暂停游戏时钟与 AI 状态机；浏览器切换后台自动暂停。 |
| `R` | 重新开始 | 胜负结算后一秒快速重置所有状态，立刻重开新一局。 |

## 3. 地图基准与空间拓扑 (30m × 22m)

```
(0,0) +---------------------------------------------------------------+ (30,0)
      |  [西走廊]            [北长走廊] (防火门 A)          [东走廊]  |
      |   病房 1             护士站                         病房 2    |
      |                                                               |
      |   (闭环内侧核心建筑群，视线与移动遮挡，设推床与药柜掩体)      |
      |                                                               |
      |  [西走廊]            [南长走廊] (防火门 B)          [安全门]  |
      |   广播目标 A         药房                           (27,11)   |
(0,22)+---------------------------------------------------------------+ (30,22)
```

- **闭环连通**：四条长走廊形成无死角的闭环主路，通道最窄宽度 ≥ 1.5 米。
- **防火门双保险**：防火门 A、B 分别跨越南北走廊中段，两门不可同时关闭，无论关哪扇门都必有一条可通行回路。
- **安全门逻辑**：前 60 秒为断电红灯状态（无法结算）；倒计时归零后通电转为绿灯，并生成地面导引光带，玩家接触触发区判定获胜。

## 4. 技术选型与运行底座

- **技术栈**：Vite + TypeScript + Three.js
- **物理与碰撞**：统一基于地图拓扑的 AABB / 射线检测（Raycasting）与网格导航图（NavGrid）
- **资产规格**：写实低多边形（Low-Poly Realistic PBR），单模型面数 3,000~15,000，WebGL 稳定 60 FPS
- **开发节奏**：遵循三阶段测试驱动（TDD）流水线推进
